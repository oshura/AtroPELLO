/*********  CYBERSEC ***********/

- Visibilidad primero: activa CloudTrail y VPC Flow Logs en los servicios críticos para tener trazabilidad de cada request. Sin registros claros no podrás distinguir entre uso legítimo y abuso ni tendrás base forense si algo sale mal.
- Control de perímetro: un AWS WAF con reglas específicas sigue siendo lo más efectivo para frenar bruteforce/DoS a endpoints públicos. Usa managed rules (CommonRuleSet, BotControl) y añade reglas propias por IP reputation, geolocalización o patrones (ej. bloquear más de N POST/minuto a /auth/*). Encadena el WAF delante de CloudFront o del ALB que sirva tu API para que filtre antes de tocar recursos caros.
- Rate limiting y bursting: para APIs expuestas publica cada operación a través de API Gateway o CloudFront Functions/Lambda@Edge con límites. Configura throttling por usuario/IP, usa API keys o tokens firmados y revoca rápidamente los que generen tráfico anómalo. Esto evita facturas inesperadas por ejecuciones en cascada (Lambda, Dynamo, etc.).
- MFA/Zero Trust para paneles y credenciales sensibles. Si alguien logra bruteforcear un login interno con solo usuario/contraseña, el impacto es total. Usa Cognito + MFA o integra SSO con conditional access. Además, aplica políticas de contraseña robustas y bloqueo tras intentos fallidos.
- Gestión de secretos: cualquier credencial que un atacante obtenga de un repositorio, instancia o variable de entorno vale oro. Centraliza en Secrets Manager/SSM, rota automáticamente y aplica IAM mínimamente privilegiado. Audita que no existan claves IAM con permisos excesivos, especialmente si se usan desde entornos expuestos.
